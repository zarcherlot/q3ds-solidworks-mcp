# G5 最终布局独立核验

状态：完成并经 G7 实机晋级（2026-08-15）。G5 私有只读验证入口和独立 C# 核验器不信任
G4 事务返回的布尔结论，不保存图纸，也不修改状态版本；九个正向案例均独立通过。

## 1. 独立预检

`verify_committed_part_drawing_layout_plan` 接受与 G4 创建完全相同的四字段请求，并重新执行
DrawingLayoutPlan Schema、规范化计划、G1 handoff、DimensionPlan、尺寸图、尺寸侧车和所有
DimensionPlan 嵌套上游文件的完整性检查。最终图纸及 `<output>.layout-verification.json` 必须存在、
路径不能与任何冻结输入重合，最终图纸文件 SHA-256 必须与侧车完全一致。

G4 验证侧车现在由固定 SHA-256 的严格 Schema 约束。G5 要求：

- 保存后的内存阶段和事务只读重开阶段都为 `verified=true`；
- 两阶段尺寸语义、视图语义和规范化布局指纹完全一致；
- 有界执行证据为连续的 1–3 轮，最后一轮必须通过；
- frozen input 清单精确包含 DrawingLayoutPlan、G1、DimensionPlan、尺寸图/侧车及
  DimensionPlan 的 handoff、源模型、上游图纸、ViewPlan 和视图验证侧车；
- 侧车中的计划、源图纸、最终图纸路径和所有哈希重新与磁盘比对。

随后 G5 从磁盘重新解析并编译上游 DimensionPlan 1.0，再运行 DimensionPlan 自身的 handoff、
ledger、持久引用和来源可信度预检。G4 唯一允许改变的是显示布局：核验器只把计划中明确的
`move_dimension` 目标位置覆盖到 DimensionPlan 的核验期望，尺寸类型、值、公差、文字、目标视图、
附着实体和持久引用仍全部来自原 DimensionPlan 和尺寸侧车。

## 2. 独立只读回读

最终图纸必须在核验开始前关闭。核验器以 silent + read-only 打开它并重建，不调用 `Save3`。第一条
独立链使用 DimensionPlan 的稳定 handle 和源尺寸侧车指纹逐项检查：

- 实际尺寸数等于原 baseline 加计划尺寸数；
- 每个尺寸的稳定身份、类型、目标视图和值仍与 DimensionPlan 一致；
- 前后缀、完整文字、精度、括号、链/基线状态、孔标注变量和公差未改变；
- 实际附着实体转换得到的模型持久引用与 DimensionPlan 附件逐项一致；
- 只有 G4 明确移动的尺寸采用新位置，其余尺寸仍采用 DimensionPlan 初始位置。

第二条独立链重新捕获 G0 原生边界和视图快照，检查计划目标位置、引线顶点包络、局部/主比例、
图幅、投影父子/轴关系、安全区、标题栏和正面积碰撞。视图类型、引用配置、显示状态、父子关系和
剖切定义指纹必须与 G4 前基线一致。最终对象 `source_id` 集合必须与 G1 完全相等，不能出现缺失、
悬空或计划外对象；视图名称集合也必须完全一致，leader 必须存在冻结拥有者。

独立快照生成的规范化布局指纹必须同时等于 G4 保存后内存阶段和事务只读重开阶段的指纹。引线附着端
仍按 0.01 mm 严格回读；仅注释侧节点允许 0.25 mm 内的 SolidWorks 原生保存归一化，且规范化之前已用
真实边界完成安全区、标题栏和碰撞检查。核验关闭图纸后
再次检查最终图纸哈希，并完整重跑 COM-free 预检，以拒绝核验期间发生的文件竞态。

## 3. 发布状态

G5 私有 verify 动词只存在于 Execution Service，不进入默认工程语义 MCP；第五个 Skill 通过 G6 的
公开布局工具调用它。截图或 PDF 不参与结构化验收，只能作为附加视觉 QA。G7 完整实机矩阵现已绑定
九次独立核验和六项安全覆盖，`plan-current.json` 已晋级为 `1.0.0` / live supported；生产 verify
可以执行，但任一计划、侧车、输出、递归输入哈希或独立读回不一致仍在提交结果前失败关闭。

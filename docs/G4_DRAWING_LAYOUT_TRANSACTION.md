# G4 C# 最终排版事务

状态：完成并经 G7 实机晋级（2026-08-15）。G4 已实现 DrawingLayoutPlan 1.0 的私有 C# 合同、
能力门禁、原生执行器和无覆盖事务；八项操作与六项安全能力现为 `supported + live`。

## 1. COM 前门禁

私有 `validate_frozen_part_drawing_layout_plan` 和
`execute_part_drawing_layout_plan` 接受 `plan`、`plan_path`、计划文件 SHA-256、由 Python 规范化器
生成的 `plan_canonical_sha256` 和 `output_path`。合同校验器按仓库 SHA-256 锁定
`drawing-layout-plan.schema.json`，编译完整八操作
联合，并强制零起点连续序号和六阶段非递减顺序。锁定对象、未经授权的视图移动/局部比例、
未经授权的主比例或不精确匹配审批记录的图幅均在 COM 前拒绝。

事务预检重新读取已发布计划并比较规范化对象，重算 G1 handoff、DimensionPlan、尺寸图和
尺寸验证侧车的文件哈希；同时递归重算 DimensionPlan 所绑定的 handoff、源模型、上游图纸、
ViewPlan 和视图验证侧车。G1 的 handoff ID、尺寸语义哈希、对象快照哈希、尺寸/对象/视图/
锁定对象清单、必需边界能力以及五项 ledger 必须与计划完全一致。尺寸侧车还必须绑定相同的
DimensionPlan ID、文件哈希、规范化计划哈希和尺寸图哈希。

独立能力门禁要求计划所用的每种操作和六项安全回读能力均为
`supported + live + evidence_sha256`，并复核 G2 清单按协议、版本和文件 SHA-256 绑定当前
G0 清单。每个计划要求的边界能力还必须在 G0 中为 `supported`。因此工程有效性和当前执行
能力保持分离；`capability_blocked` handoff 可以通过完整性检查，但创建会在接触 COM 前失败。

## 2. 原生有界执行

执行器只实现计划允许的变化：

- 用稳定 G1 `source_id` 定位尺寸、注释和引线拥有者；尺寸与注释写入冻结位置，引线计划按
  “附着端 → 注释端”表达并严格回读附着端；SolidWorks 对其余节点的保存归一化限定在 0.25 mm；
- 移动明确授权的视图；若原视图位置锁定，事务仅在赋值期间临时解锁并立即恢复原锁状态，随后回读
  位置、父视图和投影轴关系；
- 设置明确授权的局部视图比例、图纸主比例和审批记录精确匹配的用户自定义图幅；
- 尺寸层级由同阶段 `move_dimension` 的确定性目标实现，不引入新的尺寸或制造注释。

每轮固定执行“应用全部冻结操作 → `ForceRebuild3` → 读取真实边界 → 尺寸/视图语义复核 →
安全区/标题栏/正面积碰撞复核”。有限调整只允许重新应用同一冻结目标，不生成新坐标；最多
三轮，超限稳定返回 `DRAWING_LAYOUT_ADJUSTMENT_LIMIT`。尺寸数量、值、稳定身份和附着数量，
以及视图类型、配置、显示状态、父子关系和剖切定义指纹均与事务前快照比较。

## 3. 原子提交

事务要求干净 SolidWorks 会话，通过 `ISldWorks.CopyDocument` 把尺寸阶段图纸复制到输出目录
中的随机临时 `.SLDDRW`，所有写入只发生在该副本。内存核验通过后执行重建和 `Save3`，关闭
临时图纸，保存后再次捕获真实边界并建立可持久化内存基准，再以只读方式重开并要求规范化布局指纹
完全一致。已授权注释/引线的规范指纹只折叠通过位置、附着端和碰撞检查后的 SolidWorks 原生保存
归一化；各阶段安全检查始终使用未折叠的真实边界。最后才把新图纸和
`<output>.layout-verification.json` 双文件移动到最终名称。

输出路径及侧车必须都不存在，且不能与任一冻结输入重合。任何复制、写入、重建、回读、保存、
关闭、重开、哈希复核或双文件移动失败都会删除临时文件和已部分移动的最终文件；尺寸阶段图纸
及全部上游制品不会被覆盖。侧车由独立的
`drawing-layout-verification.schema.json` 描述，记录计划/输入/输出哈希、最多三轮执行证据、
内存核验和只读重开核验。

## 4. 发布状态

G4 的私有动词没有加入默认工程语义 MCP；公开五工具编排属于 G6。G7 九正一负实机矩阵完成后，
生产 `plan-current.json` 已晋级为 `1.0.0`：八项操作和六项安全能力全部绑定 live 汇总证据并标记
`supported`。G0 当前 `1.1.0` 的十一项边界也全部为 `supported`，因此生产最终排版创建可通过能力
门禁；工程计划、授权、递归哈希或真实读回任何一项不满足时仍失败关闭。

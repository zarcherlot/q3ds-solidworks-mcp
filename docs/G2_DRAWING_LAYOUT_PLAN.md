# G2 DrawingLayoutPlan 1.0

状态：完成（2026-08-15）。G2 只冻结最终排版计划的协议、领域边界、能力门禁和发布原语；不包含 G3
坐标求解，也不包含 G4 SolidWorks 写事务。

## 输入绑定

每个计划必须以绝对路径和 SHA-256 绑定唯一的 G1 `drawing-layout-handoff.json`、上游
`dimension_plan.json`、已核验尺寸图 `.SLDDRW` 和尺寸验证侧车。计划还冻结 handoff ID、配置名、尺寸语义
快照、尺寸 ID、排版对象快照、对象 ID、视图名、锁定对象，以及本计划求解和核验所依赖的 G0 边界能力。

这些绑定用于确认排版阶段只改变布局，不会悄悄换用另一份尺寸计划、图纸、配置或对象集合。

## 唯一合法操作

DrawingLayoutPlan 1.0 只包含以下八种操作：

1. `move_dimension`：移动已有尺寸文字，保持附着关系；
2. `move_annotation`：移动已有注释；
3. `route_leader`：调整已有引线路径，保持附着关系；
4. `move_view`：移动显式授权的视图，保持投影对齐；
5. `set_dimension_hierarchy`：设置尺寸层级和稳定堆叠序号；
6. `set_view_scale`：调整显式授权视图的最简整数比例；
7. `set_sheet_scale`：在计划获得显式授权时调整主比例；
8. `set_sheet_format`：按授权 ID、图幅 ID、宽和高精确匹配一次已记录审批。

操作 ID 必须唯一，序号必须从零连续且按序存储。操作只能引用冻结清单中的对象、尺寸和视图，锁定对象不能成为
目标。协议没有删除对象、创建制造注释、改变尺寸值或修改模型的操作类型。

## 不可弱化的不变量

执行策略的所有安全值都是 Schema 和领域模型常量。计划必须在任何不一致、不支持操作或布局违规时失败，并保持：

- 尺寸数量、数值、附着实体；
- 配置、显示状态、投影法和剖切定义；
- 模型关联和冻结几何；
- 上游图纸与源模型只读；
- 禁止删除、禁止新增制造注释、禁止覆盖、禁止部分提交。

## 能力门禁

`drawing_layout_planner/capabilities/plan-current.json` 是 G2 原生执行能力清单，独立列出八项操作能力和六项强制
安全回读能力。它按协议、注册表版本和文件 SHA-256 绑定 G0 边界清单；任何绑定漂移都会令清单加载失败。

评估器同时检查三层能力：计划实际请求的操作、全部强制安全回读、计划声明必需的 G0 边界。任意一项不是
`supported` 时，工程上合法的计划仍可发布为不可变制品，但执行状态必须为 `capability_blocked`，
`require_supported` 会明确拒绝进入创建事务。

G2 完成时，G4/G5 尚未提供写入和保存重开证据，因此操作与安全能力均为 `planned`。G0 已确认
`dimension_display_bounds` 不支持精确文字 glyph extent；要求该边界的计划会另外报告
`boundary.dimension_display_bounds`。不得以近似边界绕过该阻断。

## 原子发布

`PlanStore` 先以严格模型重新验证候选，再将规范 JSON 写入目标目录内的临时文件并刷盘，最后使用原子硬链接抢占
`drawing_layout_plan.json`。目标已存在时必须失败，不能覆盖冻结计划；临时文件会在成功或失败后清理。
发布目录必须已存在，且不能是仓库 `validation/` 或其子目录。

## G3 接口边界

G3 确定性引擎应消费 G1 handoff 的布局输入和本合同的不变量，按既定优先顺序求解合法操作及最终坐标。G3 可以
生成上述八类操作，但不能扩展操作联合、弱化执行策略、修改能力清单结论或提前调用 SolidWorks 写接口。

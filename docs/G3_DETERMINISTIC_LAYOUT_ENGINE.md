# G3 确定性工程图排版引擎

状态：完成（2026-08-15）。G3 将 G1 的真实边界快照和上层布局意图确定性地编译为 G2
`DrawingLayoutPlan 1.0`。它不调用 SolidWorks COM，也不修改图纸；原生应用、重建和回读属于 G4。

## 输入与信任边界

`drawing-layout-planning-request-1.0` 只允许调用层提供；对应的
`drawing-layout-planning-result-1.0` 严格区分发布、拒绝、执行就绪度、逐项门禁、审计哈希和能力阻断：

- 固定的 G1 `drawing-layout-handoff.json` 路径和文件 SHA-256；
- 请求 ID、最终计划 ID、固定创建时间和一次性发布目录；
- 可移动/可缩放视图、主比例和已批准图幅授权；
- 尺寸、注释、引线、视图、比例及图幅的优先级和偏好候选；
- 非规范性的假设说明。

调用层不能改变网格、搜索上限、最小间距、可读性阈值、阶段顺序或制造语义策略。尺寸移动意图必须引用 G1 对象
中完全一致的 `dimension_id`，并要求一个冻结的 `attachment_point_sheet_m`，否则无法执行尺寸穿越检查，求解器会
失败而不是猜测。

求解前，引擎重新读取并校验 handoff 合同、handoff 文件哈希、五项上游制品当前哈希、DimensionPlan 协议/ID/
配置连续性，以及 handoff 所绑定 G0 能力清单与当前 G3 注册表的版本和字节 SHA-256。handoff 为
`capability_blocked`、必需边界不精确或任一冻结文件变化时，其余门禁均不运行。

## 冻结规则集

`drawing_layout_planner/rulesets/deterministic-layout-v1.json` 是仓库拥有的不可调运行规则：

- 坐标网格：1 mm；
- 最大搜索环：40；
- 坐标规范化精度：9 位小数；
- 最小文字高度：1.8 mm；
- 最小箭头尺寸：1.0 mm；
- 六阶段顺序和每种 G2 操作所属阶段。

规则集按原始文件字节计算 SHA-256，写入 `producer.ruleset_sha256`。仓库 `.gitattributes` 将该目录固定为 LF，
防止跨平台换行转换造成 provenance 漂移。规则集 ID、阶段目录、操作映射或数值类型/范围被篡改时，引擎拒绝启动。

## 确定性求解

每一阶段先按优先级降序、稳定对象 ID 升序处理。偏好坐标先吸附到网格，再按固定曼哈顿代价和方向次序搜索有限
邻域。高优先级对象首先占用合法空间，低优先级对象确定性地避让。引线计划统一按“附着端 → 注释端”表达；
若意图与 G1 原生路径一致则保留完整冻结路径，否则从附着点和偏好终点生成水平优先、垂直优先、直接连接三类
候选，并选择第一条合法路径。

固定阶段如下：

1. 设置尺寸层级并移动尺寸文字；
2. 移动注释/标签并路由引线；
3. 移动显式授权的视图并保持冻结投影轴；原生事务负责恢复其原位置锁状态；
4. 按调用层候选顺序选择第一个合法局部比例；
5. 对明确使用主比例的视图选择第一个合法主比例；
6. 选择第一个与授权记录完全一致且容纳最终几何的图幅。

比例求解必须有当前比例的 G1 读回。图幅变化根据原图纸四边安全余量重建安全区，并按右/上边锚定规则移动对应
图框和标题栏保留区。未授权候选不能进入操作序列。

## 最终状态门禁

求解完成后不会直接发布。验证器从最终预测状态重新运行以下独立门禁：

- 操作严格遵循六阶段顺序，序号从零连续；
- 所有可碰撞对象完整处于安全区；
- 不侵入图框、标题栏或其他冻结保留区；
- 任意两项精确边界不存在正面积重叠；
- 尺寸附着点到文字位置的路径不穿越无关视图；
- 投影视图父子图无环，水平/垂直对齐及偏移不漂移；
- 对象间、文字到几何、对象到图框满足 G1 三类最小间距；
- 文字高度和已路由引线箭头尺寸达到规则集阈值。

G1 冻结快照中已经存在且在求解后未新增、未恶化的几何问题按稳定 gate/code/reference 记录为基线，不要求 G3
伪造一次全图重排；这项豁免不适用于可读性，也不允许产生新的安全区、保留区、碰撞或间距问题。任何新门禁失败
都返回结构化 gate/code/reference，结果为 `rejected`，不创建 `drawing_layout_plan.json`。全部通过时
才构建严格 G2 计划、评估独立原生能力清单并原子发布。能力尚未获得 G4/G5 实机证据时，计划可合法发布但保持
`capability_blocked`；G3 不能提升能力状态。

## 确定性与 G4 交接

相同 handoff 字节、相同请求和相同规则集产生相同操作类型、坐标、候选选择和规范 JSON。G4 必须按计划序号执行，
不得重新解释优先级、改变求解坐标或补充未计划操作；实际 SolidWorks 重建后的真实边界若与预测不一致，只能进入
G4 文档规定的有界回读调整或稳定失败流程。
